Storage: how the worker reads & writes media

Filesystem Libraries

Media is on a shared NFS/SMB mount or local disk.

Docker: mount the media path READ-WRITE:

-v /mnt/media/movies:/media/movies

Critical: must be :rw (default). Read-only mounts fail at the swap step.

Path differs? use TF_PATH_MAP:

TF_PATH_MAP='{"/media/movies":"/host/path"}'

S3 Libraries

Media is in S3. No shared filesystem needed.

Add to the docker run or uv command:

-e TF_S3_ENDPOINT_URL=... -e TF_S3_REGION=... -e TF_S3_ACCESS_KEY_ID=... -e TF_S3_SECRET_ACCESS_KEY=... -e TF_SCRATCH_DIR=/scratch

For Docker, add -v /tmp/transcode-scratch:/scratch (or a faster local SSD path).

Prerequisites

  • ✓ Docker & Docker Compose (if using Docker) OR uv + Python 3.12 + ffmpeg (if using bare metal)
  • ✓ Network — the worker can reach this scheduler at
  • ✓ Storage access — filesystem mount OR S3 credentials (see above)
  • ✓ Hardware encoder (optional) — Intel QSV, NVIDIA NVENC, or CPU (slower)
